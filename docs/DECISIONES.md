| 2026-11-05 | J | El sistema de diseño al día es el zip exportado por el fundador: **132 componentes** (bundle sincronizado el 2 nov 2026), compilados a `React.createElement` con estilos en línea, + tokens + 73 íconos. Guardado en `docs/diseno/design-system/components-web/`. | Es la fuente para portar `packages/ui`. Reemplaza al artifact viejo de 67 componentes. |
| 2026-11-05 | L | **El código es la fuente de verdad del sistema de diseño** desde la Fase 0 (`packages/ui`). El proyecto de Claude Design queda como referencia visual congelada. Pantalla o componente nuevo: se compone con el sistema y se aprueba con captura real antes de conectar; lo aprobado entra a `packages/ui`, al README del sistema y a la pantalla en el mismo turno. Si algo se diseña en Claude Design, se exporta y se porta; nunca se edita el mismo componente en los dos lados. | Fin de los «SINCRONIZAR». |
| 2026-11-05 | B | **Un solo código (monorepo), web + Capacitor, cuatro apps publicadas:** To'Latino (vecinos + sitio web), To'Latino Negocios (Panel v2), To'Latino Repartidor (repartidor del negocio), To'Latino Puerta (portero, solo escanea). El Super Admin es solo web (`/admin`). Nada en React Native. | Cada app = una cáscara de Capacitor con su ícono y nombre apuntando a una entrada de la misma app. 4 fichas por tienda; Apple $99/año, Google $25. Se pueden publicar por etapas. |
| 2026-11-05 | M | **Dos proyectos en paralelo: uno de PRUEBAS y uno REAL (producción).** Todo se programa y se aprueba en el de pruebas; solo lo aprobado pasa al real. | Dos entornos completos y separados (base de datos, sitio, apps, claves). Nada se construye ni se prueba directo en el real. |
| 2026-11-05 | N | **Guardianes automáticos permanentes.** El fundador trabaja solo, así que el proyecto tiene guardianes que operan dentro de él de forma continua: vigilan errores, generan reportes y proponen o aplican la corrección de problemas inmediatos. | Son parte del proyecto, no un extra: se construyen con el código y se mantienen en cada fase. Detalle (qué vigilan, dónde corren, cómo reportan) se cuadra en el plan. |
| 2026-11-05 | O | **Construir lo nuestro; pagar solo lo que no se puede replicar.** Regla permanente: siempre se piensa como las grandes plataformas, que tienen su propio sistema completo. Se paga por servicios que no podemos replicar (ej. envío de SMS). Todo lo demás —mapas, geolocalización, búsqueda, avisos, imágenes, etc.— lo construimos nosotros, sin importar lo que cueste construirlo. | Antes de usar cualquier servicio externo se pregunta «¿podemos construirlo?»; si sí, se construye. La lista de lo que sí se paga queda explícita en el plan y es corta. |
| 2026-11-05 | P | **Competimos con los grandes (DoorDash, Instacart, Walmart, Uber, etc.). Nada que no esté a su altura.** Siempre se busca la manera de crear una solución mejor que la del líder, para que el cliente tenga una razón real de pagar por el servicio. | Toda pieza se mide contra el líder de su categoría antes de construirse y antes de darse por terminada; «suficiente» no es un estado aceptable. |
| 2026-11-05 | Q | **Seguridad siempre:** el código debe ser seguro en todo momento. | Revisión de seguridad en toda pieza que toque cuenta, dinero, permisos o datos personales; nada sale sin ella. |
| 2026-11-05 | R | **Optimización: la plataforma más rápida del mercado.** | La velocidad es un requisito de cada pantalla y cada consulta, medido, no una mejora posterior. |
